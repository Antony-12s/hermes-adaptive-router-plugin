# Decisions

- The Desktop interface lives in the unified HARP package, not as a second routing owner. It uses HARP's own authenticated Dashboard API and never calls the account-pool plugin.
- Desktop enablement is opt-in and separate from the Python plugin gate. Missing `HARP_CONFIG` leaves routing inactive; the page explains the missing usage collection without inventing defaults.
- The local daily token budgets remain observational. Quota is shown per account: each row carries its own session and week windows from HARP's read of that pool credential (read automatically when the page opens, at most every 5 minutes, and on Live usage). There is no separate shared provider-quota table.
- The Desktop view follows Accounts' compact header, summary cards, status-marked account rows, and quota meters.
- HARP owns four account actions on the Hermes credential pool: Live usage (read-only per-credential usage), Balance now (bench at 90% or more, never the whole pool below 100%, release HARP benches, order by usage; no change without readings), Wake (Anthropic only, one 1-token request to accounts whose session window is idle, 10-minute cooldown), and Add account (relays Hermes' own `hermes auth add`; tokens never reach HARP or the renderer). Balance and Wake require confirmation in the page.
- Row actions are HARP-owned too: sign in again (new login takes the old label, position and schedule; the old login is deleted only after success), park (Hermes pool hold with reason `harp-parked`, optional end time), weekly park schedules applied by `hermes harp tick` from a per-user Task Scheduler task "HARP Timer" (installed while any schedule or alert channel is on, removed when none is), and remove (confirmed). Tokens, 24 h and Used by come from HARP's own post_api_request tracker (`harp-activity.sqlite3`), which counts from installation onward.
- HARP balance marks its benches with `[HARP balance]` and releases only its own benches. Run only one balance owner at a time; the account-pool balance timer was inactive when this was added.
- Page layout: the top row picks Diagram or a provider (Type-safe = jev, anthropic, Codex); the second row picks Accounts & usage, Activity, Report, Health or Alerts. Activity is HARP's own change log (30 days). Report groups HARP-tracked tokens by account, model, source and session, with a 7-day hourly heatmap and, when the timer records usage snapshots, each account's peak and minutes at 90% or more. Health runs checks from local state only. Alerts send Windows notifications and/or Telegram (`hermes send`) once per condition; the HARP Timer reads usage every 5 minutes only while an alert channel is on.
- Type-safe (jev) accounts are API keys, not sign-ins. Add account asks for a name and a masked key, checks it with TypeSafe's free GET /v1/models, and only then saves it to Hermes' pool (creating providers.jev with base_url https://api.typesafe.ai/v1 on first use). Replace key keeps the entry's name, position and schedule. TypeSafe has no usage or balance API, so Live usage is a key check and Balance/Wake are off for Type-safe; spend is in the TypeSafe console.
- Router (Diagram tab): each new message gets a pick of provider, model and effort. A working Jev (Type-safe) key makes Jev decide whatever the local learner is unsure about and teaches it; with no key, a rejected key, or Jev down, the local learner (TF-IDF over character n-grams, works for Thai) decides alone. It learns from Jev's answers and from the user's Right/Wrong feedback, and user-confirmed messages are sent back to Jev as examples. Provider load = each account's plan weight (x1/x5/x20) times its unused share; work moves off a provider above the limit. Default is Shadow (record only). Apply only rewrites model and effort on the session's own provider through llm_request middleware, using Hermes' own Anthropic thinking mapping; cross-provider switching is not done because the hook cannot change provider. Jev calls are capped per day (300 default).
- Tokens card gained an estimated $ cost and a request count, computed from the calls table (model+tokens) with a rough blended $/1M-token table in pool_state.estimate_price (opus/sonnet/haiku/fable, gpt-6 family, mini); unknown models show no price line. requests_24h and price_24h ride on get_accounts next to tokens_24h.
- Summary tab (first in the top row): every provider at a glance. Cards for tokens/cost/requests across all providers, usable accounts, the account+window with the least left (with countdown), and Jev state. One section per provider: anthropic and Codex show remaining % (100 - used) per 5-hour and weekly window with its own reset countdown; Type-safe shows the key check. It reuses /accounts per provider and the same 5-minute read-only live refresh as the provider tabs.
- Summary tab gained an Activity heatmap (GitHub-style hour x day grid, Week/Month toggle) combining token counts across every provider: dashboard.pool_state.combined_chart(db, providers, days) generalizes the per-provider _chart to any day count; endpoint GET /activity/heat?span=week|month.
- Activity heatmap toggle has a third option, 24 h (single-day, span=day -> combined_chart(..., 1)).
- Fixed the Activity heatmap overflowing its panel: repeat(24,minmax(8px,1fr)) had a hard pixel floor per column that could exceed the container; changed to minmax(0,1fr) inside an .harp-heat-wrap (overflow-x:auto, max-width:100%) and capped the grid at max-width:760px, matching the Account Pool reference.
- Fixed a real CSS bug in the heatmap fix above: min-width:100% beats max-width per spec, so the 760px cap never applied and the grid stretched full page width into thin sliver cells. Removed min-width; kept width:100% + max-width:760px so it shrinks on narrow viewports and caps on wide ones.
- Heatmap row labels show only the day name (Mon, Tue...); the mm-dd date moved to a title tooltip on the label, since consecutive days made the printed date redundant.
- Summary's per-provider section header now puts the title and its 'Open <provider>' button on the same row (title as a Fragment with a grow span and the button), matching the sketch the user drew. Section.title accepts any node, not just a string.
- Month view in the Activity heatmap replaced the 30-row x 24-col hourly grid (unreadable) with a GitHub-contribution-style grid: weeks as columns, Sun-Sat as 7 rows, one cell per day (summed tokens/requests), aligned to real calendar weeks using the client clock since the backend only sends MM-DD + weekday name. Week and 24h views keep the hourly grid.
- Replaced the GitHub-contribution-style month grid with a real calendar month: weekday header row Su-Sa, weeks as rows, date numbers in each cell, out-of-range days muted, today ringed. Bug found and fixed: building the day array with raw ms subtraction (now - k*86400000) while the grid cells use calendar setDate() arithmetic breaks across a DST transition (an hour's drift makes the last day miscompare); both now use the same today.setDate()-based construction so there is no drift in any timezone.
- Activity switched to style B (user picked from 4 mockups): a GitHub-contribution-style grid with 5 discrete levels (not a continuous gradient), square cells, hour labels every 6h, and a Total (bar + number) column per row. Unified the same grid component across 24 h (1 row), Week (7 rows) and Month (weeks as rows, Mon-Sun columns, dashed padding outside the 30-day window, ring on today) instead of three different renderers. Colors use --ui-accent at 4 opacity steps rather than hardcoded GitHub green, to match the rest of the HARP UI. The Report tab's separate per-provider HeatMap/harp-heat-cell is untouched.
- The anthropic/Codex provider tabs now show quota the same way the Summary tab does: remaining ('32% left', bar drains as it's used) instead of used ('68% used', bar fills). Swapped WindowCell/Meter for the existing LeftCell/LeftMeter in the provider accounts table, and renamed the tab's 'Highest session/week' stat cards to 'Lowest session/week left' with a left-percent value, matching Summary's 'Least left' card. Removed the now-dead WindowCell (Meter itself is still used by the peak-usage mini chart).
- HARP's router now skips delegate_task subagents (agent._delegate_depth > 0): the advanced-delegation plugin's model_map owns subagent model choice, HARP owns main chat turns. Without this, HARP apply mode rewrote the subagent's model back within the same provider and shadow mode spent Jev's daily cap on subagent goals.
- Cost ladder (dashboard/ladder.py, on by default; `ladder: false` returns to the candidate list): the router rates a message with a difficulty tier 0 to 6 instead of picking a model. Each tier has one rung per provider, cheapest first, from the providers' official prices and effort names (low, medium, high, xhigh, max). Cheap models think harder before work moves to a pricier model. The effort-to-token multipliers behind the cost order are estimates (a third-party Opus 5.5 benchmark; max is assumed). From tier 2 the provider with more weighted quota left runs the job; a heavyweight preference applies from tier 3; a provider with every account at the limit is skipped. Easy work stays on Anthropic. Focus caps the tier (Save 2, Balanced 4, Best 6). An unsure learner leans one tier up instead of jumping to Opus. Jev answers one choice question over the seven tiers. User corrections and verified runs teach tiers: a correction names a tier or a ladder model, and a verified run teaches the tier of its model and effort. The tier learner is seeded with a hint per tier and uses softmax temperature 400, chosen by cross-validation on the synthetic training prompts (the router default of 60 over-routed), so recheck it on real traffic. Max effort and the Fable and Astra rungs are untested by the dataset. The Hermes thinking mapping for xhigh and max was not verified; if it rejects a level, apply mode changes nothing for that turn.
- 2026-11-23: Anthropic plan names come from /api/oauth/profile (organization_type, rate_limit_tier), cached 6 h per account by token hash, because Hermes' Anthropic usage reader (/api/oauth/usage) never sets a plan. The manual plan picker stays as a fallback for accounts the profile cannot classify.
- The Routing provider cards share the available row width; avoid a fixed maximum on `.harp-load`, which leaves an empty strip in wide panes. Keep the responsive two-column grid.
- 2026-11-26: The HARP Timer can switch accounts automatically (off by default). Every 5 minutes it benches accounts at 90% or more and puts the one with the most left first, because Hermes fill_first only rotates after a 429. Alerts below 90% warn before the switch.
- 2026-11-26: HARP stops on an Anthropic credits_required 429 (e.g. Fable without usage credits) through transform_api_error_classification: no retry, no account rotation, and a message asking which model to use. Hermes read it as a rate limit and benched every account.
- 2026-11-27: Idle OAuth accounts showed "No reading" because their access token expired and HARP reads usage read-only. HARP now renews an expiring token through the pool refresh before reading, and puts a bench back afterwards because Hermes clears the status on refresh. A chat call also starts a balance (at most once a minute) so an account that crosses 90% steps aside before the next call, not up to 5 minutes later.
- 2026-11-24: Delegated tasks with no saved work type are always rated by Jev (jev_always), not only when the tier learner is unsure. The learner was sure and wrong on agent-written task text, and a Jev call is far cheaper than a task on the wrong tier. The Jev daily cap still applies.
- 2026-11-24: HARP is also a model provider (`provider/`, kind model-provider). The picker model is the focus (harp-save/balanced/best). HARP's pre_llm_call binds the picked rung onto the turn with Hermes' bind_route_entry (the voice-route mechanism), so the turn runs natively on Anthropic or Codex, and Hermes restores HARP at the next turn start. Unbound calls (auxiliary tasks on `auto`, a failed bind) go to the cheapest rung through call_llm, so nothing leaks to the config default and HARP never reads a credential. Picking HARP is consent to route, so the router switch and shadow mode do not apply, and no quota notice is sent (the Desktop auto-switch would move the session off HARP). A proxy was rejected: it would need OAuth tokens.
- 2026-11-28: Auto-balance is on by default and the HARP Timer installs itself on the first page load. Settings has a Set up fallback button that appends every other signed-in OAuth provider (Codex and Claude at the tier-3 rung, Nous Gemini) to Hermes fallback_providers, so a safety-filter block or outage moves to another provider without manual config.
